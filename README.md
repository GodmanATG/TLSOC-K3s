# TLSOC K3s — Kubernetes Cluster Deployment

> Migrated from Docker Compose to a production-grade Kubernetes cluster using k3s.
> Runs perfectly on 1 laptop. Automatically gets stronger when you plug in more.

# OPTION A — Windows + WSL 

This is the path for you. k3s runs inside WSL, you control everything from PowerShell or the WSL terminal.

## Step 1 — Open WSL

```powershell
# From PowerShell:
wsl
```

You are now in a Linux terminal inside Windows.

## Step 2 — Navigate to the TLSOC-K3s folder

```bash
# Your Windows D: drive is mounted at /mnt/d/ inside WSL
cd /mnt/d/Summer\ Of\ Code\ 2026/TLSOC-K3s
```

## Step 3 — Install Docker inside WSL (if not already)

If you have Docker Desktop installed with "Use the WSL 2 based engine" enabled in Settings, Docker is already available inside WSL. Verify:

```bash
docker --version
# Docker version 28.x.x — you're good
```

If not installed:
```bash
sudo apt update
sudo apt install -y docker.io
sudo usermod -aG docker $USER
# Log out and back in, or run: newgrp docker
```

## Step 4 — Install k3s inside WSL

```bash
curl -sfL https://get.k3s.io | sh -s - \
  --write-kubeconfig-mode 644 \
  --disable servicelb
```

Verify k3s is running:
```bash
sudo kubectl get nodes
# NAME            STATUS   ROLES                  AGE
# <your-hostname> Ready    control-plane,master   1m
```

**Important — Fix kubectl permissions:**
```bash
# k3s writes its kubeconfig to /etc/rancher/k3s/k3s.yaml
# Copy it so kubectl works without sudo:
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $(whoami):$(whoami) ~/.kube/config
export KUBECONFIG=~/.kube/config

# Add to your .bashrc so it persists:
echo 'export KUBECONFIG=~/.kube/config' >> ~/.bashrc
```

Now verify without sudo:
```bash
kubectl get nodes
# Should show your node as Ready
```

## Step 5 — Generate Secrets

```bash
bash generate-secrets.sh
# ✅ Generated: k8s/01-secrets.yaml
```

## Step 6 — Build the Engine Image and Load into k3s

```bash
# Build the Docker image
docker build -t foss-soc-engine:latest ./engine/

# Load it into k3s's container runtime (k3s uses containerd, not Docker)
docker save foss-soc-engine:latest | sudo k3s ctr images import -

# Verify it loaded
sudo k3s ctr images list | grep foss-soc-engine
```

## Step 7 — Deploy Everything

```bash
# Option A: Use the deploy script (does everything automatically)
bash deploy.sh

# Option B: Apply manually step by step
kubectl apply -f k8s/00-namespaces.yaml
kubectl apply -f k8s/01-secrets.yaml
kubectl apply -f k8s/02-configmaps.yaml
kubectl apply -f k8s/03-elasticsearch.yaml
kubectl apply -f k8s/04-kafka.yaml
kubectl apply -f k8s/05-redis.yaml
kubectl apply -f k8s/06-shared-pvc.yaml
kubectl apply -f k8s/07-foss-engine.yaml
kubectl apply -f k8s/08-logstash.yaml
kubectl apply -f k8s/09-kibana.yaml
kubectl apply -f k8s/11-rbac.yaml

# Create the setup-files ConfigMap (dashboards + SIEM rules)
kubectl create configmap setup-files \
  --from-file=dashboards.ndjson=./setup/dashboards.ndjson \
  --from-file=rules.ndjson=./setup/rules.ndjson \
  --from-file=logo.png=./setup/logo.png \
  -n tlsoc-ops \
  --dry-run=client -o yaml | kubectl apply -f -
```

## Step 8 — Wait for Pods

```bash
# Watch pods come alive (takes 3-5 minutes)
watch -n 2 kubectl get pods -n tlsoc

# Expected output when everything is ready:
# NAME                      READY   STATUS    NODE
# elasticsearch-0           1/1     Running   <your-hostname>
# kafka-0                   1/1     Running   <your-hostname>
# redis-0                   1/1     Running   <your-hostname>
# kibana-xxxxx              1/1     Running   <your-hostname>
# logstash-xxxxx            1/1     Running   <your-hostname>
# foss-engine-xxxxx         1/1     Running   <your-hostname>
```

## Step 9 — Run Setup Job

```bash
kubectl apply -f k8s/10-setup-job.yaml

# Watch the setup progress:
kubectl logs job/tlsoc-setup -n tlsoc-ops -f
# Wait until you see: 🚀 TLSOC IS READY!
```

## Step 10 — Access Kibana

```bash
# Port-forward Kibana to your Windows browser:
kubectl port-forward svc/kibana 5601:5601 -n tlsoc
```

Now open in your Windows browser: **https://localhost:5601**

```

```

Click the **TLSOC** space tile after login.

# OPTION B — Native Ubuntu 

## Laptop 1 — Control Plane (Do This First)

```bash
# 1. Clone or copy TLSOC-K3s to the laptop
git clone https://github.com/GodmanATG/TLSOC-K3s
cd TLSOC-K3s

# 2. Install Docker
sudo apt update && sudo apt install -y docker.io

newgrp docker

# 3. Install k3s as the control plane
curl -sfL https://get.k3s.io | sh -s - \
  --write-kubeconfig-mode 644 \
  --disable servicelb \
  --tls-san $(hostname -I | awk '{print $1}')

# 4. Fix kubeconfig
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $(whoami):$(whoami) ~/.kube/config
export KUBECONFIG=~/.kube/config

# 5. Update Kafka advertised IP to this laptop's WiFi IP
WIFI_IP=$(hostname -I | awk '{print $1}')
echo "Your WiFi IP: $WIFI_IP"
# Edit k8s/02-configmaps.yaml → set KAFKA_ADVERTISED_HOST to $WIFI_IP

# 6. Deploy the full stack
bash deploy.sh

# 7. Get join token for other laptops
echo "═══════════════════════════════════════"
echo "JOIN TOKEN (give this to Laptop 2 and 3):"
sudo cat /var/lib/rancher/k3s/server/node-token
echo ""
echo "SERVER IP: $WIFI_IP"
echo "═══════════════════════════════════════"
```

## Laptop 2 and 3 — Worker Nodes

# Troubleshooting

## Pod stuck in Pending

```bash
# Check why:
kubectl describe pod <pod-name> -n tlsoc

# Common cause: PVC not bound. Check storage:
kubectl get pvc -n tlsoc
# If STATUS is "Pending", the StorageClass may not be available.
# Verify: kubectl get storageclass
# k3s should show "local-path" as default
```

## Pod stuck in CrashLoopBackOff

```bash
# Check logs:
kubectl logs <pod-name> -n tlsoc --previous

# Common causes:
# - Elasticsearch: vm.max_map_count too low (the initContainer should fix this)
# - Engine: image not loaded (check: sudo k3s ctr images list | grep foss-soc)
# - Logstash: can't reach ES (check if ES pod is Ready first)
```

## Setup Job keeps retrying

```bash
# The job retries because ES or Kibana isn't ready yet. This is NORMAL.
# Watch it:
kubectl logs job/tlsoc-setup -n tlsoc-ops -f

# If it fails 15 times and gives up:
kubectl delete job tlsoc-setup -n tlsoc-ops
# Wait for ES and Kibana pods to show READY=1/1, then:
kubectl apply -f k8s/10-setup-job.yaml
```

## Can't access Kibana from Windows browser

```bash
# If port-forward dies, restart it:
kubectl port-forward svc/kibana 5601:5601 -n tlsoc

# If using WSL, make sure you're accessing https://localhost:5601
# (WSL port-forwards are accessible from Windows automatically)
```

## Reset everything and start fresh

```bash
bash teardown.sh
# Then: bash deploy.sh
```

# Configuration Changes & Common Scenarios

## Switching Kafka: Internal vs External
By default, the cluster deploys its own internal Kafka broker. If you want the Engine to pull logs from an **external** Kafka server (like `192.168.10.57`) instead of the internal one:

1. Open `k8s/02-configmaps.yaml`.
2. Find the `engine-config` section.
3. Change the `bootstrap_servers`:
   ```yaml
   # Internal Kubernetes Kafka:
   bootstrap_servers: ["kafka.tlsoc.svc.cluster.local:9092"]
   
   # External Kafka Server:
   bootstrap_servers: ["192.168.10.57:9094"]
   ```
4. Apply the change and restart the Engine:
   ```bash
   kubectl apply -f k8s/02-configmaps.yaml
   kubectl delete pod -l app=foss-engine -n tlsoc
   ```

**Important Note on Offsets:** By default, the engine uses `auto_offset_reset: "latest"`, meaning it only reads *new* logs that arrive after it connects. If you connect to an external Kafka and want to read all the historical logs sitting there, change this to `"earliest"` in the ConfigMap before restarting the Engine.

## Connection Refused vs NoBrokersAvailable
If you connect to an external Kafka and the Engine logs show `NoBrokersAvailable`, run this raw network test from your WSL terminal to diagnose:
```bash
timeout 3 cat < /dev/tcp/192.168.10.57/9094
```
*   **Connection Timed Out:** Your laptop cannot route to that IP (VPN issue, wrong Wi-Fi, routing).
*   **Connection Refused:** Your laptop reached the server perfectly, but the server actively rejected the connection because Kafka is turned off, blocking the port via firewall, or only listening on localhost (`127.0.0.1` instead of `0.0.0.0`).

# What Changed from Docker Compose

| Docker Compose | Kubernetes (this repo) |
|---|---|
| `docker compose up -d` | `bash deploy.sh` |
| Services in one YAML | 12 separate manifests applied in order |
| Named volumes (local disk) | PersistentVolumeClaims (StorageClass managed) |
| `./certs/` host-path mounts | Kubernetes Secrets (base64 encoded) |
| `./logstash/pipeline/` mount | ConfigMap with pipeline embedded |
| `.env` file for passwords | Kubernetes Secrets (secretKeyRef) |
| `depends_on` for ordering | Startup probes + retry logic |
| setup runs as a service | Kubernetes Job (runs once, exits) |
| No scaling | HPA for Logstash, KEDA for Engine |
| Single machine only | Multi-node cluster via `k3s agent` |
